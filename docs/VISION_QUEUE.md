# 识图与入队

状态：识图 API 已在代码里。有图的回合必须等识图有结果，再把这条回复写入发送队列。这一步还没做。发送任务本身见 [SEND_QUEUE_REQUIREMENTS.md](SEND_QUEUE_REQUIREMENTS.md)。

## 识图

放弃智谱识图。智谱只保留生图。要看的图和这句话一起交给当前模型的原生多模态。

DeepSeek 有图的回合使用 `deepseek-flash`。图片只放在 user 消息的 `image_url` 里，形式是 `data:类型;base64,...`，`detail` 为 `auto`。`assistant` 历史不能带图。不能看图的模型不发图，并在正文里说明没看到。

接受 JPEG、PNG、GIF、WebP，以文件头判断类型。QQ 图床自己的跳转可以跟着走，下一跳仍须通过下面的地址检查。其他地址的跳转拒绝。Pillow 或本机 Python 不可用时，上述四种格式的原图仍送给模型。

地址只接受 http 或 https，不能带账号、密码或端口，长度不超过 8192。主机必须是 `multimedia.nt.qq.com.cn`，或 `qpic.cn`、`qlogo.cn`、`qq.com`、`qq.com.cn` 及其子域。消息里的地址不合格时，用 OneBot 的 `get_image` 再取一次。单张不超过 8MB。一回合最多 12 帧，多张图时每张少取几帧。

读不到就记下原因。正文按文字时间线接，写明没看到画面，不编造画面内容。不能因为旁边有一张没读到的图就整轮不入队。

官方识图说明：<https://api-docs.deepseek.com/guides/vision>。第三方中转站的普通对话和识图格式见 [RELAY.md](RELAY.md)。

## 等识图再入队

没有图片的回合，正文就绪就写入发送队列。

有图片的回合，先等识图结束，再把这一轮的回复写入发送队列。结束只有两种：

- 画面已经交给模型，正文按看到的内容写成
- 已经确定读不到，正文写明没看到，并且没有编造画面

没结束之前，不把这条回复放进发送队列，也不先发一句「还在看」再改成看完之后的正文。那是覆盖。

识图进行中不被后一条消息、新的接话或戳一戳取消。后一条等待。这条看完后入队，后一条再入队。

入队的是识图之后的结果。正文从此固定，发送队列不能再改它。队列满了也等到这条结果入队，不能只记跳过。

来源过滤、按人禁回、白名单、额度、工作时段和主人已人工接话，仍在决定发送之前拒绝。等识图不绕过这些核验。

## 顺序

1. 核对账号、方向、白名单、真实 @ 或允许的接话、运行代次和额度。
2. 没有图片：生成非空正文，写入发送队列。
3. 有图片：先下载并识图。成功就按画面写正文。失败就写明没看到。
4. 正文非空之后写入发送队列。
5. 按入队顺序发送。发出的正文与队列里的正文一致。

## 验收

用合成身份和本机夹具，不向真实会话发消息。

- 有图的回复出现在发送队列时，识图已经结束：要么附上了画面，要么已经记下未读取。
- 识图结束后，队列里的正文不被另一段正文替换。
- 读图失败时，本来要回的那一轮仍入队一条说明没看到的非空回复。
- 没有图片的回复不必等待识图。
- 识图尚未结束时再来一条消息，前一条仍会在看完后入队。
