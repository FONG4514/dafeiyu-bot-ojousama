# 体验需求实施计划

顺序分三档。细节和已定边界见 [EXPERIENCE_REQUIREMENTS.md](EXPERIENCE_REQUIREMENTS.md)。同一档里靠前的先做。

## 一、影响使用

1. **消息不被吞。** 保持一个工人。后一条可以等，同一群还没开始的主动接话可以换成最新一条，但更早的发言要留在时间线里。队列满了不能直接丢掉。
2. **接话。** 「没必要回」的权重调低，能接上就回。没读到画面时按文字接，不能整轮沉默。
3. **识图。** 放弃智谱识图，改用当前模型自己的多模态。
4. **人设。** 大小姐的态度不要扩散到主人身上。本轮只留发言人和被点到的人。
5. **记忆方向。** 私聊可读该用户相关的群记忆。群聊不可读私聊。
6. **来源过滤。** 每个群可填不接话的 QQ，计数前生效，避免两个机器人对吵。
7. **戳一戳。** 单独处理，不占用普通回复的工人。
8. **按人接话。** 不接、只在 @ 时接、上限、频率、更容易接话。与来源过滤共用一份名单。

## 二、优化体验

9. **登录。** 一个 exe 自己填能拿到的连接项，含 OneBot。人只填模型 API 和扫码。
10. **日志和思考。** 已实现。Debug 才输出详细日志。思考过程输出是单独开关，默认关，只写到面板。思考等级为关、低、高、最大。提示词可查看、可编辑仍是需求。
11. **花费。** 已实现显示 token，并在填了单价后显示金额。单日、单周金额上限到了就不再调用模型。
12. **记忆。** 可查看。整理只出候选，删除要用户确认，也可自己勾选。非超级记忆不整库放内存。
13. **热重载。** 改配置不打断已经开始的回复。
14. **多 API。** 每个私聊、每个群可选。失败时换备用，不发半截回复。
15. **本机时间。** 问现在几点、今天几号时，程序透传时间、日期和时区。
