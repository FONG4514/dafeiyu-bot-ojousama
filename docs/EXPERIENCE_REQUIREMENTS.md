## 接话

- 没读到画面时按文字接，写明没看到，不能编造。不能因为旁边有图就整轮沉默。
- 「没必要回」的权重调低。能接上话题就回。来源过滤、按人禁回、白名单和额度仍可不回。
- 保持一个工人。后一条等前一条。同一群还没开始的主动接话可换成最新一条，更早的发言留在时间线里。队列满了丢掉算吞消息，不能这样。
- 每个群可填不接话的 QQ，计数前生效：不触发 @、不触发接话、不增加计数。用 QQ 号，不靠昵称。按人设置共用这份名单。
- 按人：不接话或只在真实 @ 时回复；回复上限和频率；指定的人更容易接话。
- 戳一戳单独做，不占用普通回复的工人。
- 人设按发言人 QQ 选。群接话用触发者的人设。`/persona` 停用。

## 识图和模型

放弃智谱识图。图和这句话一起交给当前模型。DeepSeek 有图的回合用 `deepseek-flash`，图片放在 user 消息的 `image_url` 里。`assistant` 历史不能带图。不能看图的模型不发图，并说明没看到。失败不编画面。

可以配置多个 API。每个私聊、每个群可选。失败时迁到备用，不发半截回复，也不改人设、记忆分区和发送核对。改配置尽量热重载，不打断已经开始的回复。

### 超级压缩

加在均衡和极速上，默认关闭，不改超级记忆。只对打开的那一个私聊或群生效。

当前会话的 token 接近**该模型的上下文上限**时才触发，不是现在的固定轮数，也不是按 8200 / 12000 字估算。触发后单独调用一次模型，不把旧摘要再截短：

- 提炼还没做完的核心目标。
- 生成一段高密度的结构化摘要。
- 把早期已经执行完的冗长对话压掉。
- 把靠反复把同一段历史塞回上下文才恢复的问题压成结论，下一轮不再整段重读。

下一轮只留仍在进行的最近几轮原话、还没完成的约定，以及摘要里点名的记忆。现有均衡压缩是每 N 轮复用学习时已经产出的短摘要，不再另调模型。

### MAX · 绝对专注记忆

第四种会话模式，默认关闭。它就是绝对专注记忆，和现有的超级记忆不是同一种。

超级记忆仍会带最近 4 条原话，并由同一个回复模型自己调用 `recall_memory`。MAX 比它更无状态：每一次对话都是新的 session。这一轮只传入两样东西：

- 聊天上下文，条数可配置，不是固定的 4 条，也不是空的。
- 另一个 AI 在数据库里找出的、它觉得适合这一轮的记忆。查找只在这个会话允许的记忆区里进行，不能越过群聊和私聊的隔离，也不能发送。

说话的模型不再靠自己的历史续接上一轮。回复的优先级高于查找。查找还没完成时，用上一份已经确认的记忆，不用半截结果。每轮多一次查找，费用和延迟更高。

### 提示词自动 RSI

默认关闭。不是提示词模板编辑。收紧的是语气，不是把人设一轮轮加重。

- **锚点**是面板里的原始人设，只读。用户在面板改了原文，锚点才换成新的第一版。RSI 的产物不能写回锚点。
- **Slot B**是当前生效、可以替换的那一版。回复用它。没有改写结果时，Slot B 就是锚点原文。

每次改写必须同时看三份：当前 Slot B、最近一段对话、锚点原文。评估永远以第一版为主，不以上一次改写的结果为主。指令写明：必须在保留原始设定核心事实的前提下收紧语气，禁止丢失基础身份设定。这样连续改写不会把「有点傲娇」收成固定口癖，也不会把面板里的关键背景提纯丢了。

只改角色和表达，不能改发送范围、白名单、真实 @、额度、记忆分区、主人识别和输出 JSON。改写结果要能对照锚点查看，并可以退回面板原文。没确认前不替换正在发送的那一轮。不把一轮道歉写成永久态度。回复优先于改写；改写没完成时，继续用上一份已生效的 Slot B。
